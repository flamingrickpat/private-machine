### Exact Story message roles (contract)

1. System — expert storyteller instruction and story constraints.
2. User — character information, background, and temporal context.
3. Assistant — prior dialogue as a story, including both Jesse and Spamuel
   utterances.
4. User — current feelings, memories, and workspace context.
5. Assistant prefill — the companion name followed by `says: "`.

The final generation continues only the companion's utterance. No tool calls.
Never store a model-invented next Jesse utterance as user input. Only accepted
dialogue enters canonical memory and public output.

Test the exact role sequence and prefix **before** testing prose quality.

### Acceptance gate

- Exact message-role and prefix tests.
- A real accepted dialogue, with the persisted result.
- Ten saved quality trials from the same initial Ghost state (independent
  trials, no mutation carry-over).
- Live quality trials finish generation before `UnitTestEvaluator` runs; the
  evaluator reads saved artifacts and never rewrites output. Scale `1` good,
  `0` borderline, `-1` poor; require ≥7 good per case, and record the
  evaluator model, rubric version, and whether it shares the generation
  backend.
- No test fails because inference exceeded a speed target. No generation
  deadline. No endpoint discovery in constructors.

  `await embed(text)`, `inspect_index(visible_text)`,
  `await prepare_index(...)`, `await search(query, visible_text)`; plus
  `cosine_similarity` and `EmbeddingCache`. Fetch only uncached text.

  `invoke(request, runtime, resume=False) -> WorkflowResult`. Python roles run

## Known gotchas

- `ShellModuleWorkflow.tools_factory` is now `(environment, batch)`. Batch may
  be `None`.
- `ShellModuleWorkflow` has `run_stop` / `cancel_run()`, `batch_provider`,
  `mcp_services_factory`, and `child_factory`.
- pm-workflows: a role that declares `tools` sees exactly those names; an
  undeclared name is a `ManifestError`. `runtime.mcp_servers` replaces shared
  `workspace/.mcp.json`. Each run gets a private per-attempt MCP config.
- `pm_coder.py` has no global `active_session`; `strip_output` is a
  `BashMachine.exec` parameter. Do not import the stale
  `pm-coder/build/lib` copy.
- Keep the application on installed GitHub packages. Do not add editable
  sibling checkouts or `PYTHONPATH` entries for final validation.
- Manifest role phases need `on_invalid: {action: stop}`.
- `MainCogLoop` does not yet route `workflow.question` / `workflow.answer`;
  that is W5.
- Keep dummy behavior clearly labeled and separate from W4 acceptance.
