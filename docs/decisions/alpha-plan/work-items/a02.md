# A02: Provide a public pm-coder decision client

## Summary

This item makes Laya available through a reusable typed Python API inside pm-coder.
It is not implemented by this plan.

Parent: [ordered alpha plan](../index.md).
Dependencies: A01.
Design: [Laya client boundary](../decisions.md#reusable-python-library).

### Deliver

1. Ship a light System One client module in the existing pm-coder distribution.
2. Expose typed ordinary Python calls, cancellation, explicit errors, and diagnostic receipts.
3. Provide a verified Laya service/demo procedure and update affected package dependencies.

D05 confirms the package location.
Do not create a separate pm-decision distribution.
The client must work without starting an agent session or importing Ghost/workflow policy.

### Start from

`C:\source\pm\pm-coder\pm_coder.py` and its single-module packaging configuration.
A separate client implementation module can remain inside that distribution.
Inspect compatible SDK support before choosing a small typed HTTP implementation.

### Verify

Use the real local binary and downloaded model.
Exercise choice, score, probability, and multi-question calls.
Verify malformed input, wrong endpoint/model, missing answers, non-finite values, transport loss, and cancellation.

Contract tests can use captured protocol fixtures.
They do not replace live inference.
Measure short and long inputs, including decisive evidence near the end.
Record build identity, model identity, timing, and effective limits.

Verify normal Python use after installing the pm-coder distribution into a clean environment.
Keep pm-workflows imports out of the client to prevent a dependency cycle.

### Manual test

Classify a concrete task report through the public Python API.
Inspect its receipt.
Disconnect the service during a second request.

### Handoff

Supply public imports, installation commands, service startup, tested limits, and exact dependency revisions.
Update pm-workflows and PM constraints/locks to tested compatible versions.
