# A11: Plan and verify durable Minecraft subtasks

## Summary

This item turns open-ended goals into revised, verified subtasks with durable evidence.
It is not implemented by this plan.

Parent: [ordered alpha plan](../index.md).
Dependencies: A03, A04, A06, A10.
Design: [task hierarchy](../minecraft.md#task-hierarchy).

### Deliver

1. Implement durable goal/story/leaf specifications with stable identities, dependency order, and acceptance conditions.
2. Add planner, selector, specialist dispatch, and independent completion verification workflows.
3. Route progress, completion candidates, replanning, and waiting through declared outcomes.

Adapt the coding workflow's task-tree pattern.
Do not reuse its Git rollback assumptions for a mutable world.
A leaf is an outcome, rather than a single tool call.
The tree accepts open-ended goal content from user appraisal and private thought.
House, farm, and mining scenarios must not become a hardcoded goal enumeration.

### Start from

`C:\source\pm\coding-workflow\agents-deploy\workflows\auto_task_v2.workflow.md`.
Inspect `planning_node_v2.workflow.md` and native planning-tree helpers.
Compare the previous `pm_next` Minecraft actor/replanner manifests.

Keep specifications separate from attempt evidence.
Child requests identify the selected leaf and specification revision.
Accepted work remains valid only while its acceptance evidence and relevant assumptions remain valid.

### Verify

Plan a small house with gathering, crafting, building, and usability dependencies.
A prerequisite must succeed before the dependent leaf runs.
Review an oversized leaf and verify controlled refinement.
Reject cyclic or missing dependencies.

A successful actor report without supporting world evidence must fail verification.
A revised specification invalidates only affected acceptance.
All decision inputs identify the exact actor/verifier attempt.

### Manual test

Inspect a real plan before execution.
Watch separate fresh actor sessions perform several leaves.
Verify the house's acceptance conditions through observation.

### Handoff

Supply tree schemas, revision rules, workflow topology, planner/verifier contracts, and live task evidence.
