# A14: Play as a cooperative survival partner

## Summary

This item verifies open-ended initiative, cooperation, refusal, and practical progress in a shared world.
It is not implemented by this plan.

Parent: [ordered alpha plan](../index.md).
Dependencies: A07–A09, A13.
Design: [cozy world and cooperation](../minecraft-operations.md#cozy-world-and-cooperation).

### Deliver

1. Verify the generic goal workflow using house, expedition, and additional self-chosen game goals.
2. Connect task choices, cooperation, refusal, and initiative to persistent appraisal and relationship state.
3. Connect world progress and away activity to companion memory and public conversation.

D03 confirms self-directed activity throughout the configured action space while the user is away.
The companion can initiate permitted goals without receiving a new instruction for each action.
It must know the difference between a shared plan and a completed result.
Cozy survival is a target experience, rather than a hardcoded agreeableness rule.
Goal choice can express resentment or mischief, including permitted destructive game actions.

### Start from

A10–A13 workflows, specialist skills, task tree, controls, and recovery.
Babymode configuration, nutrition, sleep, and diagnostic observations.
Current dialogue context and causal memory.

A diamond expedition includes preparation, resource constraints, failed searches, recovery, and return.
A house includes usability evidence, rather than only a screenshot of blocks.
Keep test-only cheat/reset commands outside actor grants.

### Verify

Run the cooperative house scenario with a mid-task footprint change.
Run a seeded diamond scenario with at least one failed method and one resupply or recovery branch.
Record actual inventory, world changes, task acceptance, and return.

Keep conversation active while the user and companion modify the same world.
Verify that user activity invalidates stale assumptions.
Compare public progress statements with the latest accepted evidence.
Verify a self-origin goal, a refused request, and a direct inventory question.
Use an actual need, deadline, or world event to trigger initiative in the main cycle.
A17 adds autonomous planning through the second conscious loop.
Use an isolated fixture for a permitted destructive goal and inspect its actual consequences.

### Manual test

Complete M4.
Spend time playing beside the companion and rate helpfulness, initiative, interruption quality, and immersion.

### Handoff

Supply complete live traces, fixture details, action-space configuration, known limitations, and the user's acceptance observations.
