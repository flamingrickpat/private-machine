# A15: Run selective codelets through the workspace

## Summary

This item activates relevant codelets and accepts their proposals through inspectable attention competition.
It is not implemented by this plan.

Parent: [ordered alpha plan](../index.md).
Dependencies: A05–A08.
Design: [codelets and shared attention](../cognition.md#codelets-and-shared-attention).

### Deliver

1. Define codelet input, activation, cooldown, cost, and typed proposal contracts.
2. Schedule a relevant subset and perform inspectable attention competition.
3. Integrate accepted nominations with the main workspace and prepare per-loop attention policy.

Use pure computations for simple triggers.
Consider Laya for measured finite classifications or candidate scoring when it improves the result.
Use generation when a codelet must construct a new interpretation or simulation.
Do not start one thread per codelet.

### Start from

Current attention nomination/frame models and stage workflow.
Inspect the old `codelets.py`, `codelet_definitions.py`, and `pathways_detailed.py`.
Reuse useful activation concepts without importing old embodied prompts.

A codelet can propose memory access, appraisal, attention, simulation, regulation, or action tendencies.
It cannot directly edit Ghost state or command Minecraft.
Its proposals carry cause, source revision, and reality attribution.

### Verify

Run competing codelets over a meaningful real event.
Inspect why one nomination won and another deferred.
Verify cooldown, elapsed-time activation, cost accounting, and stale proposal rejection.

A thought-origin trigger must remain distinguishable from an outside event.
A relevant event should change the selected set.
Resource contention must not make urgent body control wait for all codelet models.

### Manual test

Inspect nominations during conversation and a Minecraft complication.
Change a codelet configuration and compare the selected attention frame.

### Handoff

Supply schema, scheduler/competition rules, console traces, resource measurements, and configuration versioning.
