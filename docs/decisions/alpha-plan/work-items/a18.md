# A18: Inspect implementation and update the self-model

## Summary

This item lets the companion inspect its implementation and maintain an evidence-backed self-model.
It is not implemented by this plan.

Parent: [ordered alpha plan](../index.md).
Dependencies: A09, A17.
Design: [self-model and reflection](../reflection.md#self-model-and-reflection).

### Deliver

1. Provide source/documentation inspection with actual repository roots, hashes, and active runtime evidence.
2. Maintain capability and self-model beliefs with provenance, uncertainty, and revision history.
3. Integrate implementation discoveries into the inner workspace and ordinary appraisal.

Reading documentation is an action inside the companion's configured space.
The self-model must distinguish intended, implemented, enabled, and actually observed behavior.
A generated architecture document cannot verify itself.

### Start from

Current workflow registry, model connections, tool grants, and runtime module construction.
Compare the old `architecture_snapshot.py` and its incorrect root/path assumptions.
Use current Ghost belief/provenance contracts before introducing another self-model store.

Give the inspector selected read access to source and documentation.
Do not expose credentials as useful self-knowledge.
Use active wiring and receipts to corroborate important capability claims.

### Verify

Inspect one implemented/enabled feature, one disabled feature, and one planned feature.
Change a configuration or source revision and verify stale belief detection.
Record exact files and evidence used for each revised belief.

Ask about consciousness and the nature of its internal processes.
The response must follow available evidence and retain philosophical uncertainty.
A cheerful and a dramatic persona can appraise the same finding differently.
Do not hardcode a required sentience verdict.

### Manual test

Ask the companion to inspect its own thought and Minecraft implementation.
Compare its explanation with the enabled system and inspection trace.

### Handoff

Supply inspector grants, source-index rules, self-model schema, refresh policy, and grounded conversation evidence.
