# Companion development priorities

## Summary

Companion quality governs the next development phase.
Conversation latency is currently acceptable to the owner.
A16 through A19 build emotional pathways, private thought, self-knowledge, and effective reflection.
Large Minecraft scenarios remain deferred acceptance work.
They do not block cognitive development that uses different interfaces.

Parent: [alpha plan](index.md).
Related: [evaluation](evaluation.md), [curated sources](cognitive-sources.md), and [decision register](decision-register.md).

## Owner direction

The owner set these priorities on 2026-10-14:

- Prioritize the quality of the eventual AI companion.
- Accept slow development conversations when they produce useful behavior.
- Preserve useful context, reasoning, memory access, and emotional complexity.
- Reduce attention to large Minecraft tasks during cognitive development.
- Put selected historical ideas directly into current work-item requirements.
- Link historical sources only when a specific passage or mechanism remains useful.

Latency and token counts remain diagnostic evidence.
They are not current conversation acceptance thresholds.
No agent can claim a speed improvement without a valid comparison.
Fewer calls, shorter context, and cheaper models do not establish better companion quality.

Repeated review without useful progress remains a behavior problem.
A slow deliberation can be useful when it explores a real conflict or changes a later choice.
The comparison concerns what the work achieves.

## Order and dependency boundary

The next implementation sequence is A16, A17, A18, A19, then companion acceptance in A20.
A15 already supplies the selective scheduler and attention competition.
Its remaining live checks retain their existing status.

A14 supplies implemented world-event and cooperation mechanisms.
A14B supplies optional direct memory tools and native draft sessions.
Neither item has full behavioral acceptance.
Their failed receipts remain evidence of limitations.

Large changed-house, clean destructive-project, and withdrawn diamond acceptance do not block A16 through A19.
An item must still verify every interface it uses.
Before an inner goal uses the Minecraft body, verify the relevant ownership, cancellation, and uncertain-outcome recovery path.
Use modest real tasks to establish that integration.

The revised dependency does not establish a repaired house or a completed expedition.
Historical M3 and M4 results remain separate from companion acceptance.
The owner can reconsider those scenarios later.

A society of interacting companions is a later deployment of the same runtime.
[Multi-persona deployment](../beta-ideas/multi-persona-deployment.md) runs one container per persona with a shared world and chat.
No alpha item builds a separate society engine.
Identity, relationship, memory, and peer events must not hardcode one user or one chat partner.

## Quality requirements

Behavior must have a traceable path:

```text
event or attributed memory
→ interpretation and competing motives
→ accepted state, goal, or attention change
→ later choice and observed consequence
```

Persuasive prose alone does not establish that path.
Internal numeric changes alone do not establish useful conversation.
Both machine evidence and human review matter.

The companion can retain negative emotions, ambivalence, reluctance, playfulness, and privacy.
An apology does not require instant forgiveness.
Regulation does not require optimism.
Persona coherence is not agreement with every request.

The public voice stays agentic under A09R.
Ontology and introspection supply context and advisory findings.
They do not introduce new sentence gates.
`false_task_result` remains the only hard speech block.
Accepted memory still distinguishes observations, beliefs, simulations, and attributed utterances.

## Resource and reliability requirements

Existing limits remain active until a tested configuration change replaces them.
An existing model-call budget is a baseline, not proof that the budget preserves quality.
Record skipped work and its reason.
Increase or revise a limit when a demonstrated mechanism needs more work.

Preserve cancellation, finite context handling, provider recovery, and urgent body controls.
Useful background work must not deadlock the application or lose an incoming user message.
No fixed conversational response deadline is introduced by this plan.

An observation deadline belongs to the test fixture.
State its reason and inspect the work before interpreting a timeout.
A timeout is neither a completed task nor evidence that the companion should use less reasoning.

## Evidence and source authority

Use the complete Spamuel seed and real inference for primary companion evidence.
Use isolated checkpoints for new scenarios.
Use the same checkpoint for distraction and restart continuity.
Keep fact assertions separate from human judgments of immersion.

The work items contain the selected design requirements.
The [source guide](cognitive-sources.md) explains each historical source's limited role.
Old summaries do not override current owner decisions or current contracts.
An old source example does not establish live behavior.
An implemented schema does not establish an active mechanism.

Performance optimization can follow quality acceptance.
Any optimization must preserve the required context and the accepted causal behavior on the same cases.
