# A16: Deliver a grounded codelet repertoire

## Summary

Expand A15's catalogue into interacting cognitive mechanisms.
Their proposals must change accepted attention, affect, beliefs, goals, or choices.
The repertoire covers positive, negative, and mixed emotions.
Useful family interactions govern acceptance.
Definition count and reply speed do not establish quality.
This repertoire is the society-of-mind simulation inside one companion.
Many simple mechanisms compete, and their interaction produces the behavior.
It is not a separate multi-agent engine.
The engineering delivery is recorded.
The implementation is described in [codelets and attention competition](../../../subsystems/codelets.md) and [codelet pathways](../../../subsystems/codelet-pathways.md).
Its evidence and open checks live in the [A16 verification](../../verification/a16-codelets.md).

## Deliver

1. Deliver roughly 24–40 useful codelets across the ten families listed below.
2. Add versioned pathways that connect accepted precursor proposals to later activation.
3. Give each codelet explicit context requirements and a typed result contract.
4. Connect selected proposals to the current state and action owners.
5. Demonstrate emotional continuity and competing motives through real conversation.
6. Record each definition's activation, effect, inactive cases, and quality limits.

The count is an initial delivery range.
When an observed behavior needs a distinct mechanism, add a definition.
Do not copy the full historical catalogue.
A15's scheduler remains the starting point.
Automatic repertoire discovery remains beta work.

## Family coverage

| Family | Required function | Example accepted consequence |
| --- | --- | --- |
| Appraisal | Interpret an event against goals, expectations, agency, and relationship history | A correction produces embarrassment and curiosity instead of automatic hostility |
| Memory | Retrieve relevant episodes, preferences, conflicts, and unresolved commitments | A previous failed repair changes the next attempted repair |
| Imagination | Compare possible outcomes and perspectives | A predicted rejection changes an approach while remaining a prediction |
| Valuation | Compare competing motives and feasible actions | Closeness competes with autonomy without collapsing into one valence score |
| Identity monitoring | Compare choices with attributed commitments and self-beliefs | The companion notices an inconsistency and can retain, question, or revise its interpretation |
| Coping and regulation | Offer reappraisal, support-seeking, withdrawal, expression, or deliberate focus | Anger persists while impulsive action changes |
| Needs | Connect implemented needs to current opportunities and conflicts | Boredom produces curiosity, play, or a private goal |
| Attention | Nominate, connect, or redirect relevant content | A relationship concern competes with an immediate practical request |
| Action tendencies | Propose approach, refusal, challenge, sharing, privacy, or play | A negative appraisal changes a concrete conversational choice |
| Narratives | Connect attributed episodes into revisable autobiographical interpretations | A repeated shared achievement influences a later commitment |

## Proposal and context contracts

Extend `CodeletProposal` only where a required effect cannot use its existing contract.
Keep semantic proposal data separate from public wording.
A short rationale can explain an interpretation.
It must not prescribe the final dialogue sentence.

Each definition must declare:

- Its family, purpose, activation evidence, and expected consequence.
- Required state fields, source categories, and temporal scope.
- Its memory view and permitted tool groups, when direct retrieval is useful.
- Its result schema, uncertainty handling, and valid silent result.
- Its pathway inputs, cooldown, and loop applicability.
- Its version and known failure modes.

Translate historical `data_aquisation` checklists into these explicit requirements.
When referring to the source field, keep its old spelling.
Missing evidence must remain visible.
Do not fabricate a memory or invent a neutral result after a failed model request.

Proposal traces must identify causes, inspected record revisions, reality attribution, and pathway version.
Record nominations that lose attention as well as winners.
A nomination cannot directly write memory, publish speech, or command the body.
An accepted downstream owner performs the effect through its existing commit boundary.

For each proposal kind, document its consumer and durable effect.
An `appraisal` label without an appraisal consumer does not establish integration.
The same rule applies to regulation, simulation, memory access, and action tendencies.
Prevent repeated consumption of the same accepted proposal from applying its effect twice.

## Pathways and persona

A pathway connects mechanisms through evidence and precursor proposals.
It is not a fixed sequence of dialogue lines.
Record which precursor increased activation and which competing pathway remained available.
Revalidate precursor revisions before accepting an effect.
Concurrent or interrupted cycles must not reuse stale pathway state.

Deliver pathways for affection, anxiety, curiosity, empathy, shame, play, persistence, pride, envy, anger, and boredom.
Include resentment, jealousy, disgust, contempt, loneliness, disappointment, relief, and mixed feelings in repertoire coverage.
One pathway can involve several supported emotions.
Map each named emotion to implemented state and an observable choice.
Document any missing state mechanism instead of inventing a label.

The old clinical pathway names are historical design material.
They are not mandatory diagnoses, personas, or complete porting targets.
Their useful mechanisms include fixation, unstable affiliation, defensive interpretation, and distancing.
Add those mechanisms only with explicit evidence and a meaningful scenario.

Personality can alter sensitivity, retrieval salience, persistence, and competing motives.
It must not alter the facts attributed to an event.
Do not force gratitude, forgiveness, disclosure, or a cheerful conclusion.

## Subjective beliefs and autobiographical interpretation

Reuse the existing belief and provenance records.
A subjective belief must distinguish an interpretation from the underlying observed event.
Retain evidence for and against it, uncertainty, and revision history.
Keep source links through coping and defensive reframing.

For example, an unchanged utterance can support a revisable belief that the user is withdrawing.
The belief must not rewrite the utterance as an actual departure.
Contradicting evidence can weaken the belief without forcing immediate emotional relief.
Repeated generated interpretations of one source do not count as independent evidence.

A narrative links episodes by relevance and proposed causes.
Distinguish observed order from inferred causality.
A single passing thought must not redefine identity or become an invented autobiography.
Demonstrate both a retained interpretation and a later revision after new evidence.

## Verify

Use real inference and the complete Spamuel history.
Define scenario facts and expected causal distinctions before generation.
Keep human quality review separate from mechanical assertions.

| Case | Required evidence |
| --- | --- |
| Disappointment, distraction, and repair | The concern survives a topic change. Repair influences a later choice without an automatic reset |
| Anger and resentment | Accepted appraisal reaches refusal, confrontation, privacy, or another permitted choice |
| Jealousy or envy | Relationship interpretation changes attention or affiliation. Original user statements remain unchanged |
| Curiosity and boredom | Competing tendencies produce exploration, play, or a new question with an identifiable cause |
| Shared achievement | Affect influences memory salience and a later cooperative commitment |
| Mixed motives | Two motives remain represented. The selected action and deferred alternative retain their reasons |
| Retrieved failure | Memory informs a simulation and then a changed method |
| Unsupported interpretation | Missing evidence stays missing. A subjective belief does not become an observed fact |
| Counterevidence | A defensive interpretation can weaken or change without deleting its history |
| Restart | Active concerns, pathway provenance, and source attribution survive the same checkpoint |

Run controlled trait comparisons with the same attributed history and inputs.
Keep the existing cheerful seed as a separate persona check.
Its different history cannot establish a trait-only effect.

Run foundation checks for scheduling, source conflicts, and commit behavior.
Run relevant real workflow gates in fresh `.runtime` directories.
Measure inference consumption without treating low consumption as a quality pass.
For every delivered family, trace at least one proposal to accepted behavior.
List inactive or unproven definitions explicitly.
