# A06: Commit affect, goals, and causal events

## Summary

This item makes cognitive appraisal and goal proposals change accepted durable state.
It is not implemented by this plan.

Parent: [ordered alpha plan](../index.md).
Dependencies: A05.
Design: [persistent state](../cognition.md#persistent-state-and-causes).

### Deliver

1. Preserve appraisal and goal proposals from stage results through the parent report into accepted Ghost state.
2. Preserve event origins, task evidence, causal references, and active-goal lifecycle.
3. Give actions stable identities and distinguish dispatch ordering from successful task prerequisites.

This item repairs the live state path.
It does not require the final emotional repertoire.
Prepare workspace contracts for later main and inner shards without implementing the second loop yet.

### Start from

`workflows/main_cognition/schemas.py`, `pipeline.py`, and `dispatch.py`.
Inspect `workflows.main_cognition.host.MainCogLoop.prepare_input`, `_stimulus_from`, and `publish_output`.
Reuse Ghost's batch validation, revisions, knoxel references, and commit receipts.

Use existing `FeatureType.SystemMessage` and `SourceKind.System` for lifecycle evidence where suitable.
Record startup, clean shutdown, boot identity, last-known activity, and elapsed gap durably.
Feed startup/gap evidence into the first main cycle, without attributing unknown stop causes to the user.
An abrupt exit records an uncertain end interval rather than a fabricated clean-shutdown timestamp.

Inspect existing mental-state change types before adding another mutable affect object.
Resolve intentions by identity and lifecycle instead of slicing their text.
Use completion receipts for real dependencies.
Distinguish accepting a goal from refusing, deferring, or revising it.
The future inner loop uses the same goal-proposal contract as main appraisal.
Supply available workflow descriptors from configuration instead of the fixed `DEFAULT_WORKFLOWS` catalogue.
This supports new alpha behavior without requiring Laya in the existing stages.
The [model policy](../model-policy.md) keeps the normal LLM as the default throughout this state path.

### Verify

A real appraisal must change persisted affect.
A real goal proposal must produce an active intention.
Restart and verify both.
Demonstrate that stale or invalid proposals cannot partly update accepted state.

A thought event remains self-origin.
A task event retains meaningful world progress and evidence.
A queued prerequisite does not release work that requires success.
Verify startup/gap appraisal after a clean stop and an abrupt process exit.
Lifecycle event replay must not create duplicate autobiographical events.
Repeated start requests with the same durable action identity do not start another task.

### Manual test

Discuss a concrete goal and an emotionally relevant event.
Inspect the accepted state and causal links.
Restart, then ask about the goal.

### Handoff

Supply report/commit schemas, migration behavior, state evidence, and compatibility tests.
