# A19C: Finish the interface for daily conversation

## Summary

Make the existing console comfortable for ordinary conversation across real days.
Finish the user flow, repair defects, and polish presentation before the personal trial.
Keep detailed operation tools available without making them the main conversation experience.
This item is planned, not delivered.

Parent: [alpha plan](../index.md).
Dependencies: A09R, A18C, [A19](a19.md), and [A19B](a19b.md).
Current guides: [operator console](../../../workflows/console.md) and [operator service](../../../subsystems/console.md).
Next: [A19D container agent](a19d.md), then the [personal trial](../personal-trial.md).

## Deliver

1. Make the character and conversation the normal entry point in the existing console.
2. Finish reliable history, composition, navigation, and return-to-conversation behavior.
3. Show understandable connection, activity, waiting, and error states.
4. Make background work and its stop/resume controls usable during conversation.
5. Keep memory, traces, and run evidence accessible for diagnosis.
6. Add low-effort feedback capture for the owner's personal trial.
7. Complete a real browser walkthrough with the owner review status recorded.

## Conversation experience

Use `pm/console/` and its existing instance and session services.
Do not build another management application.
Remove hardcoded persona and user assumptions from ordinary presentation.
Use the chosen instance's actual names and character information.

Preserve conversation history across browser reload, reconnect, and worker restart.
Show useful dates, day boundaries, and message order.
Keep session changes distinct from a memory reset.
All sessions of the same instance still share its memory.
Make a resumed conversation easy to find after an overnight absence.

Preserve an unsent draft across transient errors and ordinary navigation.
Show whether a submitted message is pending, accepted, or answered.
Recover uncertain submissions without silently duplicating user input.
Do not lose newer input while another exchange or background workflow runs.
Use readable text, keyboard controls, clear focus, and stable scrolling.
Keep the layout usable at desktop and narrow browser widths.

## Activity and controls

Show actual operation state in plain language.
Distinguish active private work, consolidation, deliberate waiting, a stopped worker, and a failed connection.
Do not use fabricated typing or progress as evidence of thought or execution.
Do not expose private thought text as ordinary chat.

Provide simple stop, resume, and restart controls for their actual supported scopes.
Label whether a control stops one run, routine cognition, or the whole instance.
Retain accepted memory and completed run evidence after interruption.
Show consolidation progress from the committed cursor and measured integrity.
The interface must not imply that unfinished work already improved memory.

Present actionable errors without requiring the user to read internal traces.
Keep a path from an error or task result to its diagnostic evidence.
Use human-facing terms in the conversation view.
Reserve implementation details for inspection views.

## Feedback and continuity

Let the owner mark a reply or episode and add a short note.
Record the associated conversation, records, revision, and time through existing identifiers.
Keep feedback under ignored runtime paths.
Do not demand a rating after every turn during ordinary use.
The detailed A20 evaluation remains separate.

Document how to start the selected character, return tomorrow, stop background work, and recover after a crash.
Document what persists and what an explicit new instance changes.
Keep real conversation text and credentials out of tracked documentation.

## Verify

Use a real worker, real inference, and a browser against the actual console.
Retain screenshots and protocol evidence under a fresh `.runtime` directory.

| Case | Required evidence |
| --- | --- |
| Ordinary chat | Several real exchanges retain persona names, order, readable output, and input focus |
| Return after absence | The same instance and conversation remain accessible after browser and worker absence |
| Reload and reconnect | History and draft survive, and an uncertain submission does not duplicate accepted input |
| Worker restart | Accepted history remains visible and new input reaches the restarted worker |
| Background interruption | A real consolidation run yields while the user continues chatting |
| Failure recovery | Provider and worker errors have understandable states and usable recovery controls |
| Multiple sessions | Conversation identity stays separate while instance memory remains shared |
| Browser usability | Keyboard, scrolling, narrow layout, and diagnostic navigation work in the browser |
| Feedback | A marked reply resolves to the correct retained evidence after restart |

A clock-controlled boundary test can cover date formatting.
The personal trial supplies the actual multi-day continuity observation.
It does not replace this item's browser, persistence, and interruption checks.
Record owner usability review honestly.
Run foundation suites, relevant real console gates, and complete HTML regeneration.
