# A19: Reflect, test hypotheses, and revise behavior

## Summary

Make reflection change beliefs or strategies through observed consequences.
The inner loop identifies a mismatch, compares explanations, and chooses a permitted intervention.
It records the predicted effect before observing the result.
It can keep, revise, or reverse the change.
This item is planned, not delivered.

## Deliver

1. Run monitor–assess–guide workflows inside the real inner loop.
2. Retrieve prior cognitive episodes and identify a concrete mismatch or successful pattern.
3. Compare causal hypotheses with supporting and opposing evidence.
4. Apply a versioned change through the existing goal, belief, attention, or configuration owner.
5. Observe later relevant behavior and evaluate the recorded prediction.
6. Retain unsuccessful experiments and demonstrate reversal.
7. Let learning affect later choices without requiring a public reflection paragraph.

## Reflection triggers and evidence

Triggers include missed preferences, expectation mismatches, repeated unsupported interpretations, stalled methods, and attention drift.
Successful repair, useful cooperation, and unexpected success can also justify reflection.
A negative mood alone is not a defect to remove.
Repeated thought alone is not proof of an unproductive loop.

Read the A18 episode evidence and A17 expectations.
Identify the difference between an anticipated result and an actual observation.
Distinguish unavailable evidence, implementation failure, a mistaken interpretation, and a deliberate personal choice.
Do not optimize every disagreement into compliance.

A reflection can compare a current episode with a similar earlier episode.
Preserve the original sources and relevant differences.
Similarity suggests a candidate method.
It does not prove that the old method applies.

## Hypothesis and experiment contract

Record these facts before the intervention:

- The triggering episode and inspected source revisions.
- The observed mismatch or success.
- At least one plausible explanation and a relevant alternative.
- Supporting evidence, opposing evidence, and unresolved uncertainty.
- The proposed change and its owning contract.
- The predicted effect and a discriminating observation.
- The scenario or future event that can supply that observation.
- The previous configuration or state needed for reversal.

Record evidence support separately from the model's expressed confidence.
Do not treat an articulate explanation as a calibrated probability.
A repeated explanation of one source adds no independent support.

Define the experiment's lifecycle:

| State | Meaning |
| --- | --- |
| Proposed | The hypothesis and prediction exist. No intervention has occurred |
| Applied | The current owner accepted the versioned change |
| Awaiting evidence | A relevant outcome has not occurred |
| Evaluated | New evidence supports, contradicts, or leaves the prediction unresolved |
| Revised or reversed | The experiment changed course with retained reasons and history |
| Interrupted | Execution stopped with its known partial state |

A timeout or missing user response can leave an experiment unresolved.
It cannot become a successful result.
A model's evaluation does not replace the actual records, file contents, or world observations.

## Permitted interventions and commit boundaries

D07 permits changes to goals, beliefs, attention, and workflow configuration.
Source modification remains a separate opt-in preference.
This item does not require automatic source rewriting or a third personality.

Permitted changes include:

- Reprioritizing, deferring, refusing, or replacing a goal.
- Revising a subjective belief or autobiographical interpretation with evidence.
- Changing a codelet threshold, cooldown, or pathway activation parameter.
- Changing an attention policy or permitted context selection rule.
- Changing a routing question or workflow resource through its versioned owner.

Identify the real reader of each changed resource.
A modified file does not establish that a running workflow consumed it.
Record the effective version at the next relevant decision.

Use optimistic revision checks at application time.
Reassess an intervention whose source state became stale.
Do not overwrite a newer user instruction or concurrent accepted change.
Keep cancellation checks beside the commit boundary.
Restart must identify whether the change was committed, published, and observed.

Preserve schema validity, current grants, body ownership, and recovery controls.
A reflected preference cannot bypass action admission.
An uncertain external effect requires reconciliation before retry.
A reversal is another versioned change.
It does not erase the original experiment.

## Learning scope

Separate creating a new supported pattern from changing an existing pattern's strength.
A new interpretation can become a sourced belief or strategy.
An existing attention or pathway parameter can change through the permitted configuration path.
Record which form of learning occurred.

This item does not require neural weight training, a new reinforcement-learning engine, or a replacement memory system.
A19B owns hierarchical consolidation, the measured memory need, and removal of duplicate live mental-state holders.
A19 records experiments and their actual outcomes so later consolidation can preserve their meaning.
It does not need A19B to exist before its own real gates can run.
The old `pm_lida.py` learning hook is a placeholder rather than acceptance evidence.
Its useful anticipation-to-outcome pattern is already part of A17.

Learning must retain context and validity limits.
A repair that works for one relationship situation need not become a universal rule.
A successful choice can strengthen a commitment without forcing every future choice to match it.
A failed experiment can weaken a hypothesis without deleting emotional meaning.

## Reflection and persona quality

The companion can notice defensive interpretation without immediately becoming cheerful.
It can choose support, privacy, a boundary, curiosity, or a changed method.
Reflection can deepen a concern as well as resolve one.

Preserve the difference between emotional truth and an external claim.
An internal worry can be an actual executed thought while its predicted event remains uncertain.
Do not convert regulation into compulsory optimism.

Measure quality through later behavior and human review.
Do not reward more reflection text, fewer model calls, or shorter latency by default.
A useful experiment must not flatten the persona into a generic assistant.
Public presentation remains agentic under A09R.

## Verify

Use real inference, full Spamuel history, and actual application changes.
Choose modest scenarios with independently inspectable outcomes.
Large house and diamond tasks are not required fixtures.

| Case | Required evidence |
| --- | --- |
| Missed preference | A traced failure produces a supported retrieval or context change. The next relevant choice uses the original preference |
| Mistaken relationship interpretation | Alternative explanations and counterevidence produce a belief revision without rewriting the user statement |
| Attention fixation | A goal conflict produces a versioned attention change and a different later selection |
| Failed anticipation | A prior expectation is contradicted. A strategy changes and its next prediction is evaluated |
| Successful pattern | A useful repair is retained with its scope and original evidence |
| Misleading diagnosis | An initially plausible intervention fails or remains unresolved. The hypothesis is corrected |
| Reversal | The previous effective configuration is restored as a new version with full history |
| Concurrent update | A stale intervention cannot overwrite newer accepted state |
| Cancellation and restart | Interrupted experiments retain their actual lifecycle without inventing an application or result |
| Persona continuity | Improvement coexists with persistent or mixed emotion and an established voice |

Introduce a repeatable mistake with a feasible correction.
Retain a comparable baseline and unchanged scenario facts.
Record the number of real trials.
Keep failed trials visible.
Use more than one later relevant observation before claiming a durable improvement.

A controlled trait comparison uses the same history and evidence.
A separate cheerful-persona run retains its different starting history.
Neither model evaluations nor diagnostic script exit codes supply human immersion ratings.

Complete M6 with its review status recorded honestly.
Run foundation suites, relevant real gates, and complete HTML regeneration.
