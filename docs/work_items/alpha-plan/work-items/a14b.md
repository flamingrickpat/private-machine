# A14B: Replace costly structured output with editable drafts

## Summary

Use small tool calls when a model repeatedly writes large structured results or repairs them after rejection.
The workflow owns an editable draft and its validators.
The runtime keeps the native agent session and returns precise backend errors after each completed turn.

Parent: [ordered alpha plan](../index.md).
Starting point: [A14](a14.md) and its [evidence](../../verification/a14-cooperation.md).
Mechanism: [tool-backed draft sessions](../../../subsystems/draft-sessions.md).
Dependencies: A14's shared draft-session mechanism and its real lifecycle checks.
Status: planned. Other workflows have not migrated under this item.

## Reason and current evidence

A14 exposed expensive Minecraft planning repairs.
The former planner had to return complete changed nodes, including repeated conditions and exact coordinates.
A small correction could require another large output.
Graph checks then rejected missing retained children or renamed stable nodes.

The real A14 draft prototype used workflow-owned MCP tools in one persistent native session.
Its first turn left the root criterion missing.
The backend rejected that draft, and the next turn repaired it without replacing the existing leaf.
The backend expanded one box into 25 exact cells and copied its condition to the root.
No accepted project specification was committed by the prototype.

Evidence: `.runtime/alpha/20261014-a14-draft-typed-tools/receipt.json` and `native/draft-turns.jsonl` in that run.
The two native turns took 26.800 and 23.594 seconds.
This establishes tool use and repair in one conversation.
It does not establish a speed improvement over the former planner on an equivalent task.
It also does not establish house completion, cancellation, restart recovery, or human acceptance.
Measure those boundaries before using this mechanism more widely.

A separate real session verified cancellation after its first MCP draft edit without a late accepted-state commit.
Evidence: `.runtime/alpha/20261014-a14-draft-cancellation-confirmed/receipt.json`.
It closed its listener endpoints in 2.203 seconds.
Restart recovery, integrated gameplay, and comparisons for other workflows remain pending.

The later integrated diamond planner exposed a cost problem despite valid draft tool use.
Its first planning turn took 1,042.879 seconds, 49 native model requests, and 106 tool calls.
It produced a large tree and then entered repeated plan review before gameplay execution.
Evidence: `.runtime/alpha/20261014-a14-diamond-first/app/managed_tasks/7dbf69a48eec4c5983ef1514eec489fe/decisions/0001-planner/native/draft-turns.jsonl`.
The operator withdrew that scenario and requested dialogue tests.
This result prevents a general efficiency claim from the smaller prototype.
Treat excessive planning scope, repeated tool context, and repeated review as measured problems in the inventory.
Small edit tools alone do not guarantee lower cost.

## Deliver

1. Inventory model outputs that are large, repetitive, or frequently rejected.
2. Measure the current cost of each candidate before changing it.
3. Migrate candidates whose measured cost justifies a tool-backed draft.
4. Keep workflow scripts, tool schemas, state, and validators beside the workflow.
5. Share only session execution, listener lifetime, cancellation, and trace plumbing in the runtime.
6. Preserve the existing accepted reports, record provenance, and commit boundaries.
7. Supply real comparisons, operating documentation, and regenerated HTML.

Do not migrate every JSON response by default.
A small reliable decision can remain a single typed model output.
Do not add a framework that requires every workflow to inherit a domain model or implement unused hooks.

## Execution contract

The reference implementation is [`pm.runs.draft_session.run_draft_session`][].
The A14 workflow example is [`workflows.minecraft_project.planning.draft.TaskDraft`][].
Inspect the actual implementation and its receipts before adopting it.

Each migrated task group supplies its own MCP setup and validator.
The tools expose small typed inputs and useful field descriptions.
Python fills generated IDs, unchanged fields, links, counters, and repeated structures when their meaning is deterministic.
Tools return the edited value or a concise error that identifies the field, record, and valid repair.
The model can inspect its draft without rewriting it.

After the agent completes a turn, validate the complete draft against the current backend state.
On rejection, continue the same conversation with the precise errors.
Retain successful edits and the native agent's normal inference retry and compaction behavior.
Do not replay successful tool calls just because a later edit failed.
The final assistant text can be brief prose; the backend serializes the accepted report.

Reuse the existing listener helper for OS-assigned ports.
Keep each listener bound for the task group's session and close it after agent cleanup.
Do not introduce port scanning or shared global ports for independent sessions.
Provider configuration and adaptation remain in `pm.llm`.
`pm/` must not import workflow code.

## State, commits, and effects

Draft edits remain separate from accepted companion state and completed task receipts.
A validator checks types, references, revisions, and workflow invariants.
The existing owner performs the durable commit after validation and a fresh cancellation check.
Retain the current source revisions and causal IDs through that commit.
Reject stale inputs with enough information to refresh or repair the affected draft.
Never silently commit against an obsolete snapshot.

Draft tools must not start tasks, publish speech, modify memory, or mutate the Minecraft world merely to repair a report.
Keep those effects behind their current accepted action or commit boundary.
An intentional effectful tool needs its existing durable identity and uncertain-outcome recovery.
Validation success does not prove that an external task ran successfully.

Define recovery for each migrated workflow.
Record whether an interrupted draft is resumed from saved edits or discarded and rebuilt from accepted state.
Keep its native session identity tied to the owning run and role.
Do not mix drafts from different cognitive cycles or managed runs.
Cancellation must stop the session, await in-flight cleanup, and prevent late commits.

## Preserve flexible behavior

This item changes how the model records a decision.
It does not add a stricter personality or speech policy.
Keep candid speech, withholding, and deliberate deception available under [A09R](a09r.md).
Keep `false_task_result` as its only hard speech block.
Do not turn draft validation into sentence review, truth policing, or an agreeableness requirement.
Refusal, mischief, and changed goals remain valid decisions when their existing contracts permit them.

## Verify

For each candidate, preserve captured inputs and define the expected backend result independently.
Use the same model configuration, source context, task size, and comparable initial state for both implementations.
Run multiple real inference trials for a normal case and a repair case.
State the trial count and retain failed trials.
For companion behavior, use the complete Spamuel history and the applicable baseline scenarios.

Measure these facts separately:

- Time to an accepted result, including listener setup, tool discovery, retries, and validation.
- Draft size, repeated tool context, and work spent planning future phases before useful execution.
- Actual input and output tokens, model requests, tool calls, and repair turns.
- Syntax, schema, reference, and stale-state rejection counts.
- Accepted-state equivalence, provenance, and actual external effects where the workflow requires them.
- Public reply latency and human quality review for changes on the conversation path.

Record unavailable token counts as unavailable.
Do not present estimates as provider usage or infer model calls from a single logical stage count.
Report medians and ranges so one unusually slow service response does not decide the result.
Investigate any regression in total latency or token cost.
Enable a migration only when the measurements show a useful benefit without breaking required behavior.
Keep the simpler current path when tool overhead outweighs the benefit.

Exercise these boundaries through the real implementation:

1. Repair one invalid field while valid edits and IDs remain unchanged in the same session.
2. Reject a stale source revision without writing accepted state.
3. Cancel during inference and during an edit, then confirm no late commit or leaked listener.
4. Interrupt and restart according to the workflow's recorded recovery rule.
5. Keep concurrent drafts isolated and preserve existing managed-run update identities.
6. Inspect actual durable records or world effects before claiming task success.

Run the root unit and contract suites from the [work-item process](../../process.md).
Run each migrated workflow's relevant real gates in fresh ignored runtime directories.
Build the complete site with `uv run --locked --with-requirements requirements-docs.txt mkdocs build --strict`.
Open `site/index.html`, inspect changed guides and API links, and verify local HTML navigation.
