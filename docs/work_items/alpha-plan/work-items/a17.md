# A17: Run the second conscious loop

## Summary

This item gives the parallel inner conscious loop its own workspace and consequential private workflows.
It is not implemented by this plan.

Parent: [ordered alpha plan](../index.md).
Dependencies: A08, A09, A14–A16.
Design: [second conscious loop](../private-loop.md#the-second-conscious-loop) and [confirmed D02](../decision-register.md#confirmed-direction).

### Deliver

1. Implement independently scheduled main and inner GWT shards with concurrent, revision-safe publication.
2. Run private goal management, speculation, theorizing, planning, and meta-management through a real inner workflow.
3. Feed accepted thoughts/artifacts into main appraisal and attention, with chosen public disclosure actions.

This is the user's second conscious loop.
It reads the main shard and its own shard.
Its attention favors private knoxels and the current mental landscape.
Use one Ghost and one companion identity.

### Start from

`workflows.main_cognition.host.InnerThoughtLoop`, `main.py`, the inner-thought manifest, and GWT models.
Inspect Ghost's current GWT storage assumptions before supporting multiple slots.
Migrate old main-only checkpoints without losing tick or knoxel references.

Use A08 temporal retrieval and A15 attention policy.
Private workflows can produce durable artifacts as well as text.
An inner goal proposal can start the generic Minecraft workflow without a user request.
Repeated causes and resource deferrals remain inspectable.

### Verify

Choose an idea-sharing action and verify that dialogue receives the selected mental landscape.

The companion chooses disclosure; raw transcripts stay outside public output.
