# A17: Run the second conscious loop

## Summary

This item gives the parallel inner conscious loop its own workspace and consequential private workflows.
It is not implemented by this plan.
It replaces the dummy inner-thought module with a real workflow.
It also adds the qualia channels that describe the companion's inner state.
The shard contract must allow a later workspace-momentum step.

Parent: [ordered alpha plan](../index.md).
Dependencies: A08, A09R, A14–A16.
Design: [second conscious loop](../private-loop.md#the-second-conscious-loop) and [confirmed D02](../decision-register.md#confirmed-direction).
Beta direction: [workspace momentum](../../beta-ideas/workspace-momentum.md).

### Deliver

1. Implement independently scheduled main and inner GWT shards with concurrent, revision-safe publication.
2. Run private goal management, speculation, theorizing, planning, and meta-management through a real inner workflow.
3. Feed accepted thoughts and artifacts into main appraisal and attention, with chosen public disclosure actions.
4. Replace the dummy inner-thought module with a real workflow that uses the old thought types.
5. Add the qualia channels as deterministic projections with a causal reportability gate.

This is the user's second conscious loop.
It reads the main shard and its own shard.
Its attention favors private knoxels and the current mental landscape.
Use one Ghost and one companion identity.

### The inner workflow is real

Today the inner loop runs only in dummy mode.
`workflows/companion.py` passes a thought period only when `cognition == "dummy"`.
The module then points at `workflows/demo/inner_thought.workflow.md`.
A real build must give the inner loop its own workflow folder and its own stages.

Port the thought operations from `pm_next`:

- `pm_next/pm_core/subsystems/thought/thought_graph.py` — 37 thought operations, temporal focus, generative and discriminatory modes.
- `pm_next/pm_core/subsystems/thought/thoughts.py` — the generative and discriminatory thought agents.
- `private-machine/pm_lida.py` `TreeOfThought` and `_generate_subjective_experience` — the first-person inner monologue step.

A thought operation is a type, not a hardcoded sentence.
A thought carries source links, uncertainty, and an experience-versus-imagination label.
Accepted thoughts return to the main loop as self-origin events.
The ordinary appraisal path gives them personal meaning.
A sad speculation can cause real sadness in the simulated state.
The speculation must not become an outside-world fact.

### Qualia channels

The qualia schema already exists in `pm/records/qualia_records.py`.
Its docstring says the full machinery lands later.
This item lands it.

A channel is a deterministic projection of one mental-state range or one knoxel-type collection.
Each cycle records the channel position, velocity, and acceleration.
A notable movement writes a quale snapshot.
A quale is reportable only when its driver features were causal or won attention.
This is the causal gate from the old `pm_next` design.

The old `pm_next` experiments are the design source:

- `pm_next/experiments/qualia/qualia.py` — the three-stage naming step.
- `pm_next/experiments/qualia/qualia_channels.md` — the channel manifold, velocity, and poison bins.

The channels give the companion a stable vocabulary for its inner state.
A later beta step can use the same channels for a deeper report.

### Workspace momentum contract

Momentum is out of alpha scope.
The shard contract must still allow it.
A shard stores its last published frame, its revision, and its decay history.
A later step can carry the last frame into the next cycle and decay it.
Do not build momentum in this item.
Read [workspace momentum](../../beta-ideas/workspace-momentum.md) for the beta direction.
