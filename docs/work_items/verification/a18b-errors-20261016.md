## Why the existing checks passed

The foundation checks establish lower-level contracts, including deliberate error behavior.
They do not establish that the application recovers from each error during a long conversation.

- [tests/unit/pm/llm/test_http_retries.py:83](https://github.com/flamingrickpat/pm_next_v2/blob/f7eb2268f3eff4c9732e76b4b1b48e241d4a4065/tests/unit/pm/llm/test_http_retries.py#L83) expects partial provider output to raise `ProviderCompletionError`.

- Reviewer calibration covers 24 narrow control judgments. Those controls do not cover this long grounding packet or the harvest/death chronology.

The JSON repair addresses malformed completed output.

These are separate failure paths.

## Repair order and evidence needed

1. Add a progress boundary for pending exchanges. Preserve deliberate silence and detect repeated cycles without useful progress.
2. Separate provider rejection from logic errors. A rejected private cycle must retain its diagnostic without ending unrelated conversation.
3. Add admission for the shared body. A new project must update, queue behind, or explicitly replace the existing owner.
4. Resolve a rejected public candidate without treating every reviewer block as an application fault.
5. Supply dated historical execution evidence to later speech reviews. Keep historical effects separate from current inventory and position.
6. Split oversized grounding evidence into explicit, traceable windows. Preserve required chronology and source identifiers.

These are proposed repairs, not implemented fixes.
Each repair needs a fresh real reproduction of its failure boundary.
Saved-transcript review can establish a reviewer repair, but it cannot establish changed companion behavior.
A19 remains blocked by incomplete execution and unresolved behavior.
