## Stage contract

Every stage is a normal Python-role workflow. It reads `inbox/request.yaml`,
builds its own messages from its own `prompts.yaml`, calls the injected
`llm_complete` tool, validates the JSON into its typed schema from
`workflows/main_cognition/schemas.py`, rejects out-of-set references, and
writes `outbox/report.yaml`.

| Stage | Typed output | Key guard |
| --- | --- | --- |
| Triage | `TriageResult` | Every stimulus classified; no default category |
| Appraisal | `AppraisalResult` | Feeling plus emotion and need deltas; evidence ids |
| Context | `ContextResult` | `candidate_ids` must be supplied candidates; no fabricated sources |
| Attention | `AttentionResult` | Nominated and selected ids must be supplied candidates |
| Goals | `GoalsResult` | `change` limited to retain/add/complete/reprioritize; no code or prompt edit |
| Workspace | `WorkspaceResult` | Focus ids must be candidates and within the attention selection; control mode limited |
| Action selection | `ActionSelectionResult` | Action type and workflow name limited; no unavailable capability claim |

The parent passes cumulative payloads: later stages receive every earlier
stage report. The parent owns the order and the dispatch ids; it contains no
prompts and no model calls.

## Typed action dispatch

`ActionDispatch` carries `action_id`, `workflow_name`, `action_type`,
`content`, `arguments`, `depends_on`, `gwt_tick_id`, `status`, and
`rejection_reason`. `content` states the action goal, not a finished reply.

`resolve_dispatches` releases or rejects against an external receipt table.
`resolve_same_cycle` releases an action only when every dependency names an
earlier released action; an unknown or rejected dependency produces a rejected
dispatch with a reason, never a fabricated completion. Scheduling actions with
no dependency are released as intent.

## What changed during implementation

The companion backend is a reasoning model. With a 2048-token completion
budget the triage stage returned empty content and raised `ModelError`, and the
attention stage failed the same way once during a full cycle. The generation
default is now 8192 tokens, and the synchronous `llm_complete` tool retries an
empty response at most once. This is a bounded retry, not an endless reprompt
loop, and no generation deadline exists.

## Remaining limits

- The terminal and `demo.py` still use dummy cognition.
- The action selection's `depends_on` labels are preserved as given; the
  parent assigns `action-<index>` ids. No stage yet emits a cross-cycle
  receipt dependency.
- The stages do not yet write proposals into a shared `GhostWriteBatch`; the
  parent returns typed dispatches only.
- Context retrieval is re-ranking of supplied `memory_candidates`; embedding
  retrieval into that candidate list is not yet wired.
- The private-ontology boundary from W4 is not yet applied to the action
  selection content.
