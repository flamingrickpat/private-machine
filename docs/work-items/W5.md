The seven stages are `triage`, `appraisal`, `context`, `attention`, `goals`,
`workspace`, and `action_selection`, in that order.

## Stage contract

Every stage is a normal Python-role workflow. It reads `inbox/request.yaml`,
builds its own messages from its own `prompts.yaml`, calls the injected
`llm_complete` tool, validates the JSON into its typed schema from
`workflows/main_cognition/schemas.py`, rejects out-of-set references, and
writes `outbox/report.yaml`.

| Stage | Typed output | Key guard |
| --- | --- | --- |
| Triage | `TriageResult` | Every stimulus classified; no default category |
| Appraisal | `AppraisalResult` | Feeling plus emotion and need deltas; evidence ids |
| Context | `ContextResult` | `candidate_ids` must be supplied candidates; no fabricated sources |
| Attention | `AttentionResult` | Nominated and selected ids must be supplied candidates |
| Goals | `GoalsResult` | `change` limited to retain/add/complete/reprioritize; no code or prompt edit |
| Workspace | `WorkspaceResult` | Focus ids must be candidates and within the attention selection; control mode limited |
| Action selection | `ActionSelectionResult` | Action type and workflow name limited; no unavailable capability claim |

The parent passes cumulative payloads: later stages receive every earlier
stage report. The parent owns the order and the dispatch ids; it contains no
prompts and no model calls.

## Typed action dispatch

`ActionDispatch` carries `action_id`, `workflow_name`, `action_type`,
`content`, `arguments`, `depends_on`, `gwt_tick_id`, `status`, and
`rejection_reason`. `content` states the action goal, not a finished reply.

`resolve_dispatches` releases or rejects against an external receipt table.
`resolve_same_cycle` releases an action only when every dependency names an
earlier released action; an unknown or rejected dependency produces a rejected
dispatch with a reason, never a fabricated completion. Scheduling actions with
no dependency are released as intent.

## Bus wiring

`MainCogLoop` invokes the real parent manifest through the shared runner with a
`tools_factory` that supplies `run_stage`. On parent success the module, not
the role, owns the bus:

- It commits one `AttentionFrameKnoxel`, one `GwtTurnRecord`, and one
  `ActionSchemaKnoxel` per released dispatch in one `GhostWriteBatch`, with the
  incoming stimulus ids and action ids in the GWT record.
- It publishes `gwt.updated`.
- It publishes each released dispatch as `action.request`, targeted at the
  dispatch's `workflow_name`, carrying the action knoxel id, GWT tick, action
  id, goal content, arguments, the stimulus records, bounded memory texts, and
  the workspace frame.
- A rejected dispatch publishes an `action.receipt` telemetry message with the
  rejection reason and no action.

`StoryDialogue` subscribes to `action.request` targeted at `dialogue_story`.
It builds the typed `StoryRequest` from the action, the triggering stimulus,
recent public dialogue, recent thoughts, and the selected memories, runs the
real `dialogue_story` workflow, and on acceptance commits one public dialogue
feature and publishes `dialogue.reply` with the action's correlation id. A
rejected candidate publishes an explicit `action.receipt` and commits nothing.

`MainCogLoop` also accepts `workflow.question` telemetry. It stores the
question as a `WorldEvent` stimulus and runs a normal cycle. A run that
suspends on `ask_user` publishes `workflow.question`; a correlated
`workflow.answer` resumes it through `ShellModuleWorkflow`.

## Lazy activation

`build_app` never contacts a model. `runtime/cognitive_model.py` holds one
`LazyStageModel` shared by the cognitive and Story workflows. The first
completion activates the configured connection on the calling module thread
and caches the client; later completions reuse it. The completion budget
defaults to 8192 tokens and an empty response is retried at most once. There
is no generation deadline and no endless reprompt loop.

## What changed during implementation

The companion backend is a reasoning model. With a 2048-token completion
budget the triage stage returned empty content and raised `ModelError`, and the
attention stage failed the same way once during a full cycle. The generation
default is now 8192 tokens, and the synchronous `llm_complete` tool retries an
empty response at most once.

The full-seed live app path showed that raw narrative and fact records are
large. `_memory_candidates` now clips each candidate text to 500 characters so
the context and Story prompts stay bounded. The first successful app-path run
saved before the clip is retained for comparison.

The final app-path run showed the Story model may append a companion thought
after the spoken line. The W4 `clean_reply` contract deliberately allows a
companion thought, so the candidate and the public reply contain both. The
dialogue is still one companion turn and one correlated reply, which is the
W5 gate. Tightening the cleaner to a single utterance is W4 follow-up, not a
W5 change.

## Remaining limits

- `demo.py` and the `cognition="dummy"` build still use the fixed keyword
  policy. It is explicitly labeled and is not the terminal path.
- The action selection's `depends_on` labels are preserved as given; the
  parent assigns `action-<index>` ids. A model-supplied workflow-name label is
  not translated into an action id, so a real cross-action dependency is still
  rejected explicitly rather than mis-resolved.
- The stages do not yet write proposals into a shared `GhostWriteBatch`; the
  parent commits the frame, GWT, and action schemas after parent success.
- Context retrieval is re-ranking of supplied `memory_candidates`; embedding
  retrieval into that candidate list is not yet wired.
- The private-ontology boundary from W4 runs in Story dialogue but is not yet
  applied to the action-selection content.
- `workflow.answer` resume is exercised by the adapter tests, not yet by a real
  managed run that asks a question.
- The Story candidate can include a companion thought line after the spoken
  utterance. This is within the W4 message contract but is not a single
  utterance.
