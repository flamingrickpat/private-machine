## W3 acceptance gate

The six remaining items are complete:

1. **Permanent-error policy.** pm-coder 0.9.2 raises `PermanentProviderError` for authentication, billing, and model-configuration rejections instead of reconnecting forever. Transient connection, timeout, 5xx, and 429 faults keep the reconnect path. The pm-workflows driver reports the typed rejection as provider exhaustion.
2. **Child namespaces and service grants.** `WorkflowRuntime.child_factory(scope)` opens the runtime for one child invocation, and `_run_child` supplies it instead of the parent runtime. A role that declares `tools` sees exactly those names; an undeclared name is a `ManifestError`. Child capability intersection (`allowed_mcp`/`allowed_effects`) is unchanged.
3. **Role-scoped Ghost proposal tools.** `ghost_mcp.build_tools(environment, batch)` reads the batch's staged view and adds `ghost_propose_create` and `ghost_propose_replace`. Proposals stay invisible to other runs until commit, and a module can supply the run's batch through `batch_provider`.
4. **Dynamic loopback MCP listeners.** `runtime/mcp_services.ScopedMcpRegistry` starts each named FastMCP service on an OS-assigned loopback port, holds the bound socket for the listener's lifetime, returns per-run HTTP descriptors, and closes them after success, error, or cancellation. `WorkflowRuntime.mcp_servers` selects a private per-attempt config instead of shared `workspace/.mcp.json` discovery.
5. **Run cancellation and waiting/resume.** `ShellModuleWorkflow` has its own `run_stop` event. `cancel_run()` cancels one run without stopping the module; module shutdown and terminate controls cancel the active run. A suspended run publishes `workflow.question`, exposes its question ID and resume phase, and resumes when a `workflow.answer` carries a durable answer receipt.
6. **Gate evidence.** See the fifth checkpoint below.

The terminal still uses dummy cognition. W3 establishes infrastructure, not companion behavior.

## Fifth checkpoint: scoped runtime services and run control

Application version 0.6.0 uses pm-workflows 0.5.0 and pm-coder 0.9.2.
This checkpoint closes W3.

pm-coder 0.9.2 adds `is_permanent_failure` and `PermanentProviderError`.
`run_turn` raises the typed error once for 401/403, 402, and model-configuration rejections instead of reconnecting every 30 seconds.
Transient connection, timeout, 5xx, and 429 faults keep the existing reconnect path.

pm-workflows 0.5.0 extends `WorkflowRuntime`:

- `tools` is the run-level Python grant; a role's declared `tools` narrow it and an undeclared name is a `ManifestError`.
- `mcp_servers` supplies named scoped service descriptors, replacing shared `workspace/.mcp.json` discovery with a private per-attempt config.
- `child_factory(scope)` opens the runtime for one child invocation; `_run_child` passes it instead of the parent's.

The application adds:

- `ghost_mcp.build_tools(environment, batch)` with `ghost_propose_create` and `ghost_propose_replace` over a real `GhostWriteBatch`; the batch view is resolved per call so earlier proposals are visible.
- `runtime/mcp_services.ScopedMcpRegistry` and `serve_services`, which hold the bound loopback socket for each temporary FastMCP HTTP server and close it after success, error, or cancellation.
- `ShellModuleWorkflow.run_stop`, `cancel_run()`, and a terminate-aware `deliver`, so one run cancels without stopping the module and module shutdown cancels its active run.
- `WorkflowRunner.invoke(..., resume=...)`, durable `pm.answer-receipt.v1` writing, and waiting question extraction. `ShellModuleWorkflow` publishes `workflow.question` and resumes when `workflow.answer` arrives with a matching question ID.
- `batch_provider` and `mcp_services_factory` module hooks, with a fresh `GhostWriteBatch` and scoped MCP descriptors per run.
