## First checkpoint: explicit coder sessions

The first change removes pm-coder's process-global `active_session`.
Each model, shell tool, and compaction call receives its session or its context budget explicitly.
Request logs no longer overwrite earlier requests.

No cognition, Ghost model, bus contract, or workflow interpreter changes in this checkpoint.
Virtual file permissions, child namespaces, MCP grants, and cancellation remain separate work.

## Second checkpoint: virtual file permissions

pm-coder 0.8.0 is published at [d0af761](https://github.com/flamingrickpat/pm-coder/commit/d0af761e7e97c3290cd791d7a57ed47e3bcbb7d1).
The application checkpoint is version 0.3.2.
Its lockfile selects that GitHub revision. pm-workflows remains unchanged at version 0.3.0.

Previously, the virtual coder file tools used administrative access and ignored the supplied workflow user.
They now use the same per-file permissions and current directory as that user's Bash commands.
Denied writes and edits preserve the original memory and access rules.
Denied reads do not evaluate lazy content.

Virtual prompt files also use the supplied user.
They never fall back to host files.
A denied child prompt produces a visible failed child record before inference.
The original administrative APIs remain available to trusted application code.
This change does not introduce inherited directory permissions or a Python sandbox.

## Fourth checkpoint: real agent targets

Application version 0.5.0 uses pm-workflows 0.4.0 and pm-coder 0.9.1.
The kernel now passes the runtime to its pm-coder role driver.
Each role uses an explicit model connection, context window, target, and cancellation signal.
Folder tools use the target root. Virtual tools use the Ghost BashMachine and its `workflow` user.
Python roles retain their existing execution path.

The coder disables automatic host instructions, skill discovery, and MCP discovery for embedded runs.
The driver supplies the selected role's text directly.
Runtime roles that request MCP services require explicit grants.
This checkpoint does not supply dynamic servers or complete role-scoped Python tools.

Cancellation interrupts supported asynchronous inference and waits for session cleanup.
Synchronous tool effects remain cooperative. Cancellation cannot undo a completed effect.
The driver propagates runtime errors to direct callers.
Live-test mode reports endpoint failures without the production reconnect loop.
