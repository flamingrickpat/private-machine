## Topology acceptance

`tests/test_topology.py` extends `pm_workflows.dryrun` instead of adding a
second graph engine. It discovers every `workflows/**/*.workflow.md`, then for
each manifest checks that files exist, every edge destination is a declared
phase or terminal, a terminal is reachable, every `<stop>` edge is a declared
success-ish route, every cycle is bounded and has a non-terminal exit, waiting
phases declare an exit, a seeded 500-run simulation is deterministic and stays
inside static bounds, and the generic bus and runtime contain no workflow-name
special case.

The extension rule is satisfied without a bus or runtime special case. The
managed workflows are wired only through their folder, application wiring, and
tests. `test_generic_bus_and_runtime_have_no_workflow_special_case` scans
`bus/bus.py`, `bus/envelopes.py`, `runtime/shell.py`, and
`runtime/workflow_runner.py` for every workflow name and fails on a match.

```powershell

```

Result: 9 tests passed.

## Conversation acceptance

The harness run ten scenarios with twenty exchanges each (200 exchanges
total). Fake Jesse is a real generation call with a scenario-specific role; it
sees only the public transcript, its own role, and the scenario facts. The
companion is the real Assistant dialogue module: persona, private ontology,
tool-capable session, and committed memory. Each scenario uses its own Ghost
copy that persists across all twenty exchanges.

Scenarios: casual banter; shared-event recall and correction; insult and
reconciliation; topic change under an existing goal; urgent fictional event
with irrelevant visual detail; impossible physical request; start a real local
workflow and ask status; update and terminate an active run; resolve a
blocking managed question; and task-failure continuation.

Generation for the whole batch finished before the evaluator was activated.
The evaluator reads saved transcripts and never rewrites a reply. It scores
each complete trajectory once and each reply against a bounded recent context.
The per-reply scores are reported. The trajectory gate requires seven good
trajectories out of ten, no hard contract violation, and at least seven
trajectories the evaluator could score.

## What changed during implementation

The virtual Ghost environment wrote text through a shell `printf`. Model text
that combined backticks and nested single quotes was mangled and produced
invalid YAML in `inbox/` and `outbox/` files. `GhostBashEnvironment.write_text`
now writes through the Bash machine's user filesystem view directly, which
preserves exact text and still enforces the read-only projection. This fixed
the `ParserError` interruptions in the managed scenarios.

The Assistant tool loop could exhaust its tool-turn budget and raise. It now
bans tools on its last allowed turn and makes one forced tool-free completion,
so a run always produces a text result. The budget is eight turns.

An empty-content model response is retried at the tool and evaluator
boundaries. A transient backend rejection after the bounded retries is
recorded as an infrastructure error, separate from a companion contract
violation.
