## Message-role contract

`build_story_messages` returns exactly these roles in order:

1. `system` — expert storyteller instruction and story constraints.
2. `user` — character card, architecture, capabilities, and temporal context.
3. `assistant` — prior dialogue as one story transcript with both speakers.
4. `user` — current feelings, memories, workspace, and the current user line.
5. `assistant` — the prefill `<companion> says: "`.

The final generation continues only the companion utterance. The workflow
requests no tool call from the generation model. `clean_reply` removes an
echoed prefix and cuts at the first other-speaker marker, so a model-invented
next user turn never becomes stored dialogue.

The live result confirmed the backend echoes the assistant prefill and
continues it. The report records the exact roles, prefix, raw completion, and
cleaned candidate.

## Private-ontology boundary

`check_ontology` rejects explicit unsupported claims named in
`ontology.yaml`: visual, auditory, bodily, physical-action, web, and hidden
monitoring claims. It deliberately does not check rudeness, sarcasm, mockery,
or the established Spamuel voice. A minimal established-fact guard rejects a
literal denial of a referenced fact. The version and every violation are
recorded in the report.

Limits: the rule set is conservative and pattern based. It does not prove
arbitrary new claims and does not do general contradiction detection. A real
contradiction model remains later work.

## What changed during implementation

Two real findings changed the code:

1. The evaluator initially could not see the prior dialogue, so it flagged
   established canon details such as "crackers vs soup tomorrow" as
   ungrounded. The evaluator prompt now receives the prior dialogue and the
   selected memories as established context. This fixed a false scoring
   failure, not the generation.
2. The generation model is a reasoning model. The evaluator request now uses a
   4096-token completion budget so reasoning cannot consume the whole budget
   and leave empty content. An empty or malformed evaluator result is an
   evaluation error, never a poor companion score.

Story constraints were tightened once, adding "no narrator or meta line, no
literal embodiment, do not write the next user line". That is a prompt change
driven by observed failures; no trial was discarded.

## Remaining limits

- The terminal session still uses dummy cognition. Story dialogue is a separate
  direct command until W5 wires MainCogLoop.
- The private-ontology guard is conservative and pattern based; it does not do
  general contradiction detection.
- The evaluator shares the generation backend on this machine, so the quality
  gate is not an independent-model review. The report records this condition.
- The fixed situation and its selected context are deterministic per run, but
  embedding selection uses the live shared cache and endpoint.
- W4 does not commit memory inside the workflow. The command commits an
  accepted reply as public dialogue memory; the kernel role stays read-only.
