## Test-first sequence and discovered problems

The initial bus tests exposed shared mutable messages, missing causation IDs, and missing target filtering.
The first Ghost batch test run failed because the batch implementation did not exist.
The existing module regression suite then passed all 32 checks after integration.

Additional boundary tests found five problems:

1. A repeated publication used IDs from unaccepted proposals.
2. A narrower batch view retained hidden revision IDs.
3. New records accepted a tick outside the batch.
4. Index reconstruction reused reserved IDs.
5. A replacement accepted a changed creation tick.

Two further tests exposed partial dialogue acceptance and missing cancellation at its commit boundary.
All seven regression cases now pass.
The concurrency checks use actual threads and actual checkpoint files.
The failed-save check uses an invalid filesystem target, not a mocked writer.

The full seed round trip compares every serialized state field after save and restoration.
It includes all 11,202 records and their mental-state arrays.
Corrupt counters, revisions, schema IDs, GWT keys, and commit keys fail restoration.

## Migration and limits

The CLI now saves accepted Ghost state by default.
Existing `build_app()` callers remain ephemeral unless they supply a checkpoint or a persistent Ghost.
The old direct mutation helpers raise errors. Callers must use `store_knoxel()` or a write batch.
The old top-level import paths remain available.

MainCogLoop no longer subscribes to its own public reply notifications.
Replies still become memory before they reach the user.
This prevents an extra empty cognitive turn after every reply.

This checkpoint supports one Ghost owner per checkpoint file.
It does not provide cross-process locking, durable bus replay, or restoration of live tool effects.
An event can repeat after repeated publication. Its memory IDs must come from the accepted receipt.

Managed-run receipts persist and restore active states as `interrupted`.
The current dummy scheduler remains an in-memory demonstration.
The real managed-run table and recovery decisions belong to W6.

The batch API is trusted host code. Role-scoped writes and shared child batches belong to W3.
The next item completes real-folder and virtual-target agent execution, session isolation, dynamic MCP lifetime, grants, and cancellation.
No live cognition or immersive dialogue acceptance is claimed here.
